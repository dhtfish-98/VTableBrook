# VTableBrook 防御用途与本轮重写范围

复核日期：2026-10-02。

## 实际防御用途

从有权限持有的兼容 ARM64 内核文件中静态解释类初始化和虚表候选元数据，用于离线故障调查、代码审阅和版本核对。

## 实际能力

运行时读取一个本地普通文件并向标准输出打印结果。没有联网、进程启动、输入文件修改或分析文件写出路径；静态解释指令不等于执行输入内核。控制字符与非 ASCII 名称字节转义输出。

## 当前重写与验证

四个 C 实现文件及共享头文件全部改为有界图像上下文：普通文件读取、Mach-O 命令/段/节边界、指令扫描、寄存器候选值和名称/13 项元数据读取。输入、指令工作量、名称、记录和报告长度均设限，错误返回 2；超过限额的报告明确为不完整。

182 次正常进程对照、230 项 ASan/UBSan 与边界检查、13 项独立汇编的操作数检查及安装后运行检查通过，详见 [VALIDATION.md](VALIDATION.md)。GitHub CI 对新提交重新运行当前检查。

## 验证边界

保留上游的高位指针归一化和初始化/分配入口约定，仅支持声明的线性内核布局。静态流程仍是有限模式解释，不模拟完整 ARM64 控制流、内存或所有未知指令/调用的寄存器影响；输出是候选值，空报告不证明没有类。没有验证真实设备或所有内核版本，也不声称任意输入安全。旧 v1.0.0 二进制包不包含本次修复，当前 v1.0.1 发布仅提供源码。
